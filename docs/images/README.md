# README showcase

`demo-showcase.png` presents Evergreen News, Evergreen Snack, and Evergreen
Lagged using device screenshots captured during demo validation. The phone
frames, background, and composition were produced with the built-in image
generation tool. This is a presentation composite, not a raw device capture.

The screenshots show the Planet Lisp feed, the sample storefront, and synthetic
sleep and heart-rate data. The sample artwork and photography retain their
existing terms; see the [News notice](../../examples/evergreen-news/NOTICE),
[Snack notice](../../examples/evergreen-snack/NOTICE), and
[Lagged notice](../../examples/evergreen-lagged/NOTICE).

## Generation prompt

Use case: compositing. Create one polished GitHub README showcase image for
Evergreen Compose, using these THREE REAL APP SCREENSHOTS as the actual screen
contents, not loose UI inspiration. Input 1 Evergreen News; input 2 Evergreen
Snack; input 3 Evergreen Lagged. Wide landscape canvas around 1800 x 1400, high
resolution crisp legible text. Background: refined very dark evergreen green
with subtle soft illumination, understated professional open-source project
presentation. Small restrained heading at upper left exactly 'Evergreen Compose',
and beneath it exactly 'Native Android apps. Written in Common Lisp.' Arrange
three equally sized upright front-facing phone screen cards in one evenly spaced
row, News then Snack then Lagged. Make the screens as large as possible, occupying
most of the image, with slim charcoal rounded frames, subtle shadows, no
perspective tilt, no overlap, generous balanced outer margins. Label below
screens exactly 'News', 'Snack', 'Lagged' in small light typography. CRITICAL:
faithfully composite each provided screenshot; preserve all existing app layout,
text, photographs, graphs, colors, controls and spacing. Crop out only the black
Android status strip at the very top and black gesture strip at very bottom of
each source screenshot, retaining the complete app UI between. Do not redesign,
improve, summarize, add or invent any elements INSIDE the screens. Do not change
or invent text inside screenshots. No decorative extra icons, no brand logos,
no badges, no trees, no hands, no watermark. The outer framing and background
should feel elegant and minimal so the real apps are the focus.
